# Security Policy

## Supported Versions

Security fixes are provided for the latest released version of `tigusigalpa/bybit-php` and the current `main` branch. Please upgrade to a supported version before reporting an issue when possible.

## Reporting a Vulnerability

Please report a suspected vulnerability privately by email to [sovletig@gmail.com](mailto:sovletig@gmail.com) with the subject line `[SECURITY] bybit-php`.

Do not open a public GitHub issue for a vulnerability before the disclosure has been coordinated. Do not include real Bybit API keys, API secrets, account information, or other credentials in a report.

Include the affected version, a clear description of the security impact, minimal reproduction steps or proof of concept, and any proposed mitigation. Examples of relevant vulnerabilities include authentication or request-signing bypasses, API-key exposure, dependency compromise, unsafe deserialization, and injection vulnerabilities.

## Disclosure Process

We aim to acknowledge a vulnerability report within 7 days. After triage, we will work with the reporter on a coordinated disclosure timeline and aim to provide a fix or mitigation within 90 days, depending on severity and complexity.

Please allow reasonable time for investigation and remediation before publicly disclosing a vulnerability. Once a fix is available, we will publish release notes and credit the reporter where requested and appropriate.
